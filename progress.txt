# Build Progress Log
Started: 2026-01-29
Feature: Админ-панель для управления токенами доступа к тренажеру МАЯК

## Codebase Patterns
- Проект использует Next.js с файловой структурой pages/api для API эндпоинтов
- Данные хранятся в JSON-файлах в папке data/
- UI компоненты находятся в src/components/
- Используется Tailwind CSS для стилизации

## Выполненные задачи

### 1. ✅ Модель базы данных (src/utils/mayakTokens.js)
Создана полная модель для работы с токенами:
- id (UUID)
- name (название токена)
- token (криптографически стойкий токен через crypto.randomBytes)
- usageLimit (лимит использований)
- usedCount (счетчик использований)
- createdAt / updatedAt (даты)
- isActive (статус активности)

Функции:
- readTokens(), saveTokens() - чтение/запись в JSON
- generateToken(), generateId() - генерация токенов
- createToken() - создание нового токена
- getTokenById(), getTokenByValue() - поиск токенов
- updateToken(), addAttemptsToToken() - обновление
- deactivateToken() - деактивация
- useToken() - использование токена (увеличение счетчика)
- validateToken() - проверка валидности
- getAllTokensWithStats() - получение всех токенов со статистикой

### 2. ✅ API эндпоинты
- POST /api/admin/mayak-tokens/generate - создание нового токена
- GET /api/admin/mayak-tokens - получение списка всех токенов
- PATCH /api/admin/mayak-tokens/:id/add-attempts - добавление попыток
- DELETE /api/admin/mayak-tokens/:id - деактивация токена
- GET /api/mayak/validate-token - проверка токена (без использования)
- POST /api/mayak/validate-token - использование токена

### 3. ✅ Админ-панель UI (src/pages/admin/mayak-tokens.js)
- Статистика: всего токенов, активных, исчерпанных
- Форма создания токена (название + лимит использований)
- Таблица со всеми токенами:
  - Название
  - Токен (с кнопкой копирования)
  - Использований (X/Y, осталось: Z)
  - Статус (Активен/Исчерпан/Деактивирован)
  - Дата создания
  - Действия: + Попытки, Деактивировать

### 4. ✅ Безопасность
- Авторизация по паролю "a12345" (для простоты доступа)
- Форма логина в админ-панели с сохранением состояния в sessionStorage
- Все API эндпоинты проверяют пароль из query или body
- Генерация токенов через crypto.randomBytes(32)

### 5. ✅ Интеграция с тренажером МАЯК
- В src/components/features/tools-2/settings.js:
  - validateTokenAPI() - проверка токена
  - useTokenAPI() - использование токена (увеличение счетчика)
- При активации тренажера токен проверяется и используется

## Исправления багов

### 6. ✅ Исправлена проблема с валидацией токена (2026-01-29)
Проблема: при вводе токена страница просто обновлялась и не давала войти.

Причина:
- useCallback для validateToken с зависимостью [token] вызывал бесконечный ререндер
- useEffect зависел от validateToken, что приводило к циклическим вызовам

Исправления в src/components/features/tools-2/settings.js:
- Убран useCallback для validateToken
- useEffect теперь имеет пустой массив зависимостей []
- Валидация при загрузке токена из cookies выполняется напрямую через validateTokenAPI
- Добавлено отображение ошибки валидации токена (красный блок)
- Добавлен индикатор загрузки "Проверка токена..." (синий блок)

### 7. ✅ Исправлен переход в тренажер с токенами из базы данных (2026-01-29)
Проблема: после ввода токена и нажатия "Войти в тренажер" страница просто обновлялась и оставалась на странице настроек.

Причина:
- В trainer.js функция checkToken использовала захардкоженный массив CORRECT_TOKENS
- Токены, созданные через админ-панель и хранящиеся в mayakTokens.json, не распознавались
- При попытке войти в тренажер, checkToken не находил токен в массиве и редиректил обратно на settings

Исправления в src/components/features/tools-2/trainer.js (строки 1669-1682):
- Заменена проверка CONSTANTS.CORRECT_TOKENS.includes(token) на вызов API
- Теперь используется /api/mayak/validate-token для валидации токена
- Токены из базы данных (mayakTokens.json) теперь корректно распознаются

### 8. ✅ Исправлен вход администратора в тренажер (2026-01-29)
Проблема: при входе через пароль администратора (fffff → a12345) тренажер редиректил обратно на страницу настроек.

Причина:
- В settings.js использовался захардкоженный токен DUMMY_VALID_TOKEN = "MA8YQ-OKO2V-P3XZM-LR9QD-K7N4E"
- Этот токен не существует в базе данных mayakTokens.json
- API /api/mayak/validate-token не распознавал его как валидный

Исправления:
1. В src/pages/api/mayak/validate-token.js:
   - Добавлена константа ADMIN_BYPASS_TOKEN = "ADMIN-BYPASS-TOKEN"
   - GET-запрос с этим токеном возвращает valid: true с неограниченными попытками
   - POST-запрос с этим токеном возвращает success: true без увеличения счётчика

2. В src/components/features/tools-2/settings.js:
   - Заменён DUMMY_VALID_TOKEN на ADMIN_BYPASS_TOKEN
   - Теперь при входе через пароль администратора используется правильный токен

### 10. ✅ Исправлен вход в тренажер при вводе нового токена (2026-01-29)
Проблема: при вводе нового валидного токена и нажатии "Войти в тренажер" происходил редирект обратно на страницу настроек.

Причина:
- При вводе нового токена он не сохранялся в cookies
- При переходе в тренажер использовался старый невалидный токен из cookies
- API возвращал valid: false для старого токена, и происходил редирект

Исправление в src/components/features/tools-2/settings.js:
- При успешной валидации токена через API, токен сразу сохраняется в cookies
- Теперь при переходе в тренажер используется актуальный валидный токен

### 11. ✅ Исправлено сохранение истории промтов (2026-01-29)
Проблема: созданные промты не отображались на странице истории.

Причина:
- В trainer.js история сохранялась с ключом "trainer_v2_history" (через getStorageKey("history"))
- В history.js история читалась с ключом "history" (без префикса)
- Несоответствие ключей localStorage приводило к тому, что страница истории всегда была пустой

Исправление в src/components/features/tools-2/history.js:
- Добавлен TRAINER_PREFIX = "trainer_v2" и функция getStorageKey()
- parseHistoryCookie() теперь использует getStorageKey("history") для чтения
- Ключ localStorage теперь соответствует ключу в trainer.js
